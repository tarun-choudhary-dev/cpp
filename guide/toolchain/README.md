# Pinned toolchain and redistribution inventory

The release uses the same `binji/wasm-clang` commit `648c4a89997a351eef75cdaec3ef5b89d4937dec` verified in Phases 1–7. The browser reports Clang 8.0.1 and LLD 8.0.1 at initialization. The host supplies the older `wasi_unstable` ABI, MemFS and a C++ sysroot. No compiler binaries, linker flags or sysroot contents are upgraded by the release build. `release-manifest.json` records every packaged file and SHA-256; `research/assets.json` in the source repository contains upstream URLs, sizes and pinned hashes. `npm run verify:assets` checks the local assets without downloading. `npm run assets` is a separate, explicit setup/download step and verifies pinned hashes before storing files.

Packaged assets live at `poc/vendor/wasm-clang/` solely to preserve the proven Worker's default relative URL. This directory contains `clang`, `lld`, `memfs`, `sysroot.tar`, upstream `shared.js`, the deterministic descriptor-forwarding `shared-patched.js`, `LICENSE` and `LICENSE.llvm`. Only the patched host file is loaded. The original host and license files are included for source/notice traceability. The patch changes `this.hostWrite(str);` to `this.hostWrite(str, fd);` to separate stdout from stderr. The runtime loads Clang, LLD, MemFS and sysroot into the Worker during initialization; later jobs use those in-memory modules.

The public API exposes C++11, C++14 and C++17; default C++17/O0. C++20/C++23 options, arbitrary flags, O3, debug controls and C++ exception options are not exposed. The legacy host has incomplete WASI services, no interactive input, no threads or processes, and a known stdin Unicode round-trip failure for `世界`. Safari is unverified. The generated Wasm uses `wasi_unstable`, not a modern Preview 1/2 ABI.

The bundled upstream `LICENSE` is Apache-2.0 text; `LICENSE.llvm` identifies Apache-2.0 with LLVM exceptions. They are shipped unmodified. The sysroot tar itself has no license/notice files. Its exact component revisions and complete corresponding notices have **not** been established from the pinned distribution. The upstream author's [build notes](https://gist.github.com/binji/b7541f9740c21d7c6dac95cbc9ea6fca) mention a wasi-sdk 5.0 sysroot, but do not prove the tar's full component inventory. Do not treat the two top-level upstream notices as a complete redistribution clearance for all sysroot contents. See `THIRD_PARTY_NOTICES.txt` in the release directory.
